# Steps M01-M04: canon in the repo, Act I deepened, and the realm engine

Issue-ready specs for S-001 to S-031 (plus the splits listed in [Index changes](#index-changes)). Each step below is
written so the plan job can paste it into one `agent:improvement` issue: the title is the step heading after the id,
and the six sections map to the issue's `## Why`, `## What`, `## Acceptance criteria`, `## Verification plan`,
`## Out of scope` and `## Risk & rollback`. The `#### Assets` block goes inside `## What`.

Order of authority: `docs/roadmap/CANON-NOW.md` LOCKED items > `docs/roadmap/CANON.md` > the
reconciliation rows in `docs/roadmap/steps/*.md` (for the topics they name, until the named close-out edits the losing
file) > the bible (`docs/roadmap/bible/*.md`) > the INDEX row > the issue. Where two bible files disagree, this
file picks one and says so in [Bible reconciliations](#reconciliations). An implementer follows the step. The
milestone's close-out step (S-007, S-015, S-023, S-031) copies each reconciliation into the bible file that lost.
INDEX.md is generated from these step files (ids, titles, dependencies, sizes, saves), so it never needs a
hand edit to match them.

Links are relative to `docs/roadmap/steps/`: bible files are `../bible/<file>.md#<anchor>`.

### S-017 · refactor: the World reads its grid size from the instance, with alias-safe hash keys

Milestone M03 · Depends on: S-016 · Size: M · Save: none · Flag: none · Bible:
[../bible/systems.md#realms](../bible/systems.md#realms), [../bible/systems.md#realm-kinds](../bible/systems.md#realm-kinds)

#### What

### S-019 · refactor: terrain, water and scenery dispose and rebuild cleanly

Milestone M03 · Depends on: S-018 · Size: M · Save: none · Flag: none · Bible:

#### What

1. **`js/terrain.js`**: `buildTerrain(W, scene)` returns `{ group, material, dispose() }`. `dispose` removes the group
   and disposes every chunk geometry, the height texture and the terrain material if this build created it. Shared
   splat textures from `Assets` are **not** disposed. `buildWater` returns `{ mesh, material, dispose() }` (geometry,
   material, height texture). `buildMapCanvas` needs no dispose; the old canvas is dropped by reference.

   plushies, secrets, reasons, boughs and thorn rings. Shared materials from `mats()` / `variants` are kept (they are
   cached programs reused by the next build); only per-build materials are disposed. Clear every `Map` and list.
3. **Debug hook** `G.debug.world.rebuild()`: disposes terrain, water and Scenery and builds them again from the same
   `G.world` (no regeneration), reassigning `game.scenery`, `G.scenery` and the water material the sky and atmosphere
   read. Returns `{ geometries, textures, ms }` from `renderer.info.memory`.
4. **New in-page suite `js/debug/tests/realm.js`** (registered in `js/debug/tests.js`; CI matrix entry
   `{ id: realm, args: realm }` added now; S-022 adds the gates). First test, "terrain, water and scenery rebuild
   with no leaks": record `renderer.info.memory` after two warm frames, call `G.debug.world.rebuild()` three times

5. Modules that hold references into the old Scenery (perf culling lists, wp9 world, grass) are rebuilt in S-020. In

### S-028 · feat: realms register their own music and ambience at load

Milestone M04 · Depends on: S-027 · Size: S · Save: none · Flag: none · Bible:
[../bible/art-audio.md#music](../bible/art-audio.md#music), [../bible/art-audio.md#music-format](../bible/art-audio.md#music-format),
[../bible/art-audio.md#voices](../bible/art-audio.md#voices), [../bible/art-audio.md#ambience](../bible/art-audio.md#ambience)

#### Why

53 tracks are written as note data in art-audio. Each land registers its own at load, so `js/audio.js` does not grow
by a land's music every time and a realm's music costs no precache bytes. ENGINE F28, part of **Realm engine II**.

#### What

1. **`js/audio.js`** (classic script):
   - `G.audio.addTrack(name, def)`: validates, compiles and stores the track; returns `true`, or `false` with a
     `console.warn` listing the problems (never throws in play). Validation per
     [../bible/art-audio.md#music-format](../bible/art-audio.md#music-format): every bar of `melody` and `counter` sums
     to `sp`; chord qualities only `''`, `m`, `7`, `maj7`, `m7`, `dim`, `sus`; every voice name exists in `V`; every
     perc letter exists in `PERC`; `from` names a known track.
   - Variants: `from: '<track>'` copies that track's data, then applies `voices { part: voice }`, `drop [parts]`,
     `add { pad?, perc?, comp?, arp2? }` and the top-level overrides (`bpm`, `swing`, `rev`, `delay`, `sparkle`,
     `leadVol`, `lead2`, `lead2Vol`, `layers`, `startLayer`, `transpose`).
   - `transpose`: semitones added at compile to melody, counter, bass, comp, arp2 and pad; a bass note under MIDI 36 is
     raised an octave.
   - `G.audio.addAmbience(name, bed)`: the shipped ambience bed shape (`wind`, `ev`); checks event names against the
     ambience sound bank.
   - The 8 new voices and 6 percussion letters (`w a p d c e`) of [../bible/art-audio.md#voices](../bible/art-audio.md#voices),
     pasted verbatim into `V` and `PERC`. A voice costs nothing until a track uses it.
   - `G.audio.track()` returns the playing track's name (add it if missing).
2. **Realm music.** `REALMS[id].tracks` (optional) is `{ name: def }`. `RealmManager.enter` registers each with
   `addTrack` before building the world (once per page). The sandbox gets:
   `tracks: { sandbox: { from: 'meadow', transpose: 2, bpm: 96, drop: ['perc'] } }`.
   `game.updateMusic()` plays `W.regions[r].music` (S-027), so entering the sandbox plays `sandbox`.
3. **Tests**
   - `js/debug/tests/realm.js` "realm music": at home in the village `G.audio.track() === 'village'` and
     `G.debug.audio.layer()` equals seeds placed; `await G.debug.realm('sandbox')` → `'sandbox'`; back home →
     `'village'` with the same layer. Headless Chromium may not start the audio context without a gesture: assert on
     the requested track name (the scheduler's state), not on sound.
   - "every track validates": loop `G.audio.check(name)` (a debug export running the validator on a stored track) over
     every shipped track and the sandbox track: no problems.
   - "bad tracks are refused": `addTrack('bad', { from: 'nope' })` and a 7-step bar in an `sp: 8` track both return
     `false`.

#### Assets

None (procedural).

#### Acceptance criteria

- Shipped tracks sound as before (the validator passes on them, and the `act1` village-layer test still passes);
  the sandbox plays its own track; bad tracks are refused with a warning.
- Invariants: *Precache* (no audio files), *Machine*.

   the shipped loaders and HD policy, resolving when done (missing files resolve too; fallbacks apply).
