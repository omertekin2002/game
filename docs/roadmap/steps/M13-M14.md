# Steps M13-M14: Pinewhistle (the land template), its side stories, Rook and the first home stories

Issue-ready specs for S-095 to S-116 (plus the splits listed in [Index changes](#index-changes)). Each step below is
written so the plan job can paste it into one `agent:improvement` issue: the title is the step heading after the id,
the six sections map to the issue's `## Why`, `## What`, `## Acceptance criteria`, `## Verification plan`,
`## Out of scope` and `## Risk & rollback` (the `#### Assets` block goes inside `## What`).

Order of authority: `docs/roadmap/CANON-NOW.md` LOCKED > `docs/roadmap/CANON.md` > the reconciliation
rows in `docs/roadmap/steps/*.md` (for the topics they name, until the named close-out edits the losing file) > the
bible (`docs/roadmap/bible/*.md`) > the INDEX row > the issue. Where two bible files disagree, this file picks one and says so in
[Bible reconciliations used by these steps](#reconciliations); an implementer follows the step, and the milestone's
close-out step (S-109 for M13, S-116 for M14) copies each reconciliation into the bible file that lost.

Links are relative to `docs/roadmap/steps/`: bible files are `../bible/<file>.md#<anchor>`.

<a id="conventions"></a>

**Conventions every step here uses** (do not repeat them in the issue; link this section):

- **Pinewhistle is the land template.** M15-M17 (Archwater, Threemills) open each land file of the same kind that
  M13 writes and mirror it. So every Pinewhistle module is written as a reusable shape with the land's data in a
  table, never land-specific code paths: `js/realms/recipes/ridges.js` (terrain), `js/realms/pinewhistle.js` (the
  realm module: music, ambience, palette, dim/restored state, rhythm), `js/realms/props-pinewhistle.js` (prop
  builders), `js/content/finds/pinewhistle.js` (find tables read by the shared `placeIsle*` passes),
  `js/content/quests/pinewhistle.js`, `js/content/dialogue/pinewhistle.js`, `js/content/scenes/pinewhistle.js`,
  `js/text/en/pinewhistle.js` (text ids `pw.*`), `js/realms/dungeons/whistlehollow.js`,
  `js/realms/hollows/pinewhistle_<n>.js`, `js/boss/mossmantle.js`, `js/realms/enemies/pinewhistle.js`.
- **Find earlier-step code by grep, not by guess.** Steps before M13 were specified in parallel. Where a step names a
  module from an earlier step (`js/realms/index.js`, `js/realms/manager.js`, `js/realms/coverage.js`,
  `js/realms/dungeon-compile.js`, `js/realms/recipes/dungeon.js`, `js/realms/recipes/lagoon.js`, `js/dungeon-mod.js`,
  `js/cond.js`, `js/content/flags.js`, `js/content/looks.js`, `js/dialogue.js`, `js/scenes.js`, `js/quests.js`,
  `js/items.js`, `js/abilities.js`, `js/gates.js`, `js/progress-graph.js`, `js/travel.js`, `js/world-post.js`,
  `js/hud/journal.js`, `js/boss/defs.js`, `js/ai/index.js`, `js/content/economy.js`, `js/realms/fallbacks.js`,
  `tests/chapter.mjs`, `js/debug/tests/realm.js`), the implementer first greps for it (for example
  `grep -rn "placeIsleChests" js/`) and uses the real path and export names. If a helper the step needs does not
  exist, the step builds the smallest version the spec needs and says so in the PR body. Duskwick (S-083 to S-093)
  shipped the first copies of the isle passes, the coverage module and the realm module; Pinewhistle reuses them.
- **Shipped code this file names was checked on `main` at `b79d73d`:** `js/player.js` (`integrate`, `fall`, `jump`,
  `canJump`, `lastSafe`/`unstick`, constants from `TUNE.move`: `jumpV` 6.12, `gUp` 22, `gFall` 32, `termV` 20,
  `airCap` 6.2), `js/phys.js` (`standOK`, `walkOK`, `moveCircle`, `passable`), `js/world-collide.js` (`bridgeAt`,
  `ground`, `standTop`), `js/world.js` (`addBridge` with `{ax, az, bx, bz, h0, h1, w, arch, id}`, the post-pass guards
  `o.<pass> !== false` at lines 130-132, `npcSpots`, `landmarks`, `addInteract`), `js/scatter.js`
  (`Scenery.buildGreatTree` builds `this.greatTree.group`, the parent for crown lanterns), `js/events.js` (`EV`),
  `js/hud/keys.js` (tokens), `js/data.js` (`ENEMY`, `NPCS`), `js/models.js` (`enemyDef`, `npcDef`),
  `assets/manifest.js`, `tests/world.test.js` (the `SLOW` group, `placementPrint`), `tests/inpage.mjs`,
  `.github/workflows/ci.yml` (`inpage` matrix).
- **Text.** Every new string is a text id in `js/text/en/<realm>.js` (`pw.*` for Pinewhistle, `home.*`,
  `side.ssNN.*`, `lore.*`), at most 220 characters, `{tokens}` from `js/hud/keys.js` only, `~` only in Miso's lines,
  `!!` only in Kinako's, Pip never speaks. Every speaker that ships here reserves its marker in
  [../bible/charter.md#reserved-markers](../bible/charter.md#reserved-markers) and the content lint in the same PR:
  Elder Nutmeg "For safekeeping!", Professor Pinfeather "Tok.", Mossmantle "...mm...", Foreman Knock "Tap-tap.",
  Rook "Called it!", Grandpa Dormy "...hwaaah...".
- **Save.** Nothing in M13-M14 changes the save schema. The save stays at **v9** (from S-071). New state goes in
  `S.flags`, `S.items`, `S.quests`, `S.collect`, `S.chests`, `S.secrets`, `S.bosses`, `S.plushies`, `S.rematches`,
  `S.travel`, `S.bestiary`, `S.dungeons`, with the id rules of [../bible/systems.md#ids](../bible/systems.md#ids).
  Every new flag key or family is registered in `js/content/flags.js` in the same PR (the content lint fails
  otherwise). Flag keys use `^[A-Za-z0-9:_.-]{1,48}$`.
- **Invariants.** Every step's acceptance criteria include "Invariants: paste the block from
  [../bible/charter.md#invariants-block](../bible/charter.md#invariants-block) and keep the lines named". The lines
  are named by their first words: *Frozen home island*, *Frozen realms*, *Hidden until whole*, *One save slot*,
  *Budgets per view*, *Precache*, *Assets*, *Tone*, *Original IP only*, *Machine*.
- **Machine.** Before any browser run: `free -h` (want ≥ 6 GB available); one browser at a time; stop every server and
  browser started. In-page runs are `node tests/inpage.mjs <suite>`, chapter runs `node tests/chapter.mjs <id>`. A new
  in-page suite is a file `js/debug/tests/<suite>.js` registered like `wp1.js`-`wp9.js`, plus one entry in the `inpage`
  matrix of `.github/workflows/ci.yml`. This file adds the suites **`beacon`** (S-095a), **`pinewhistle`** (S-096,
  extended by every later M13 step), **`glide`** (S-102a) and **`side`** (S-110, extended by every M14 step), and the
  chapter **`ch-pinewhistle`** (S-106b).
- **Art.** Painted images are generated inside the step by a GPT Sol subagent (T3 orchestrator `delegate_task`, Codex
  `image_gen.imagegen`) or a Gemini model, with the fixed preamble of
  [../bible/art-audio.md#preamble](../bible/art-audio.md#preamble) + the kind suffix of
  [../bible/art-audio.md#kinds](../bible/art-audio.md#kinds) + the subject given in the step. Processing follows
  [../bible/art-audio.md#pipeline](../bible/art-audio.md#pipeline) (the white-key one-liner, `tools/slice_sheet.py`,
  `tools/export_sprites.py`, `tools/make_seamless.py`, `tools/process_strip.py`, Pillow webp). Raw generations are
  never committed; the prompt and the processing commands are appended to `docs/art/prompts.md`; turnaround reference
  sheets go to `docs/art/ref/<key>.webp` (never under `assets/`). Every key gets `realm: 'pinewhistle'` (or `home`
  for home-only art) and a fallback entry in `js/realms/fallbacks.js`. 3D is code-built (`js/models.js`,
  `js/props.js`, `js/toon.js`, the rig families of [../bible/cast.md](../bible/cast.md)) with the ART BRIEF pasted in
  the PR body; GLB slots are added to `assets/manifest.js` **commented out** with their height. Pip's GLB is never
  touched.
- **Coordinates.** Metres, `x` east, `z` south (north is `−z`), bearings clockwise from north `θ = atan2(x, −z)`.
  Pinewhistle's local frame is `u = (x − z)/√2` (toward NE), `v = (x + z)/√2` (toward SE). "`near(A, r)`" means the
  atlas anchor rule ([../bible/atlas-isles.md#conventions](../bible/atlas-isles.md#conventions)): nearest valid 1 m
  cell to `A` within `r`, choosing among the five nearest with the pass's own RNG.

## M13 · Pinewhistle: the first isle (land template)

**Goal.** Build the land template once, completely, on Pinewhistle: beacons and the eight crown lanterns that are the
whole game's progress bar, the `ridges` recipe (two ridges, a misty ravine of rope bridges, a sawmill stream, the
Whistling Pine), its painted look and wind-flute music, the Acornets and their professor, four new species, every
find, the Leaf Glider (and the three home finds it opens), the 12-room Whistlehollow inside the pine, Mossmantle,
the people → depths → Warden → Kindle loop with the first beacon beat, three Hollows, the progression solver over the
whole realm graph, and performance checkpoint 3. Archwater and Threemills (M15-M17) copy every file of this
milestone.

**Entry criteria.** M12 closed (S-094 stacked or merged): Duskwick unhidden with `ch8` and its chapter test green;
the chart lists Pinewhistle as a fog bank; the save is v9; the shared Lamplighter kit (S-082), the Lantern (S-057),
abilities and gates (S-048), the dungeon engine (S-049 to S-053), the boss framework (S-043 to S-045), Hollows
(S-073), travel (S-080, S-081) and the isle finds passes and coverage test (S-086) exist.

**Exit criteria.**
- `REALMS.pinewhistle.hidden === false`; `tests/fixtures/realm-prints/pinewhistle.json` frozen; coverage, POI density
  (≥ 120 POIs on ≈ 150,000 m²), solver and realm-suite views pass.
- `whistlehollow` and `hollow_pinewhistle_1..3` compile, solve (exit, boss door, every chest) and pass the realm suite.
- `node tests/chapter.mjs ch-pinewhistle` passes in CI; the chain test links `ch8` end → `ch-pinewhistle` start.
- `bun test tests/progression.test.js` walks the whole shipped realm graph from a fresh save with no sibling-tool
  dependency.
- Perf checkpoint 3 is recorded in `docs/roadmap/progress.md`; `docs/roadmap/briefs/batch-05.md` is written.

**What the player can do at the end.** Sail to Pinewhistle (the chart's fog bank lifts), hear that the Acornets
cannot sleep since the pine went quiet, free the sawmill's jammed wheel, mend Mossy Span so Professor Pinfeather can
cross with the knot-hole score, play the pine's tune on its root door, climb Whistlehollow on plate-switched updrafts,
find the Leaf Glider, calm Mossmantle, kindle the pine's beacon and hear the pine sing; see the first crown lantern
light at home; hear Granny Wick read Lamp Log 2 and Hoot begin his star count; glide to the Blossom Run, Tern Stack
and the Old Stump at home; solve three Hollows (two heart petals, one gem bag); explore 14 chests, 4 keepsakes,
3 vistas, a bottle, 2 Lamp Logs and 5 benches.

**Playtime added.** +5.0 h: the Pinewhistle main chain 4.0 h (people 1.0 h, Whistlehollow 1.75 h, Mossmantle and
the kindle 0.25 h, travel and exploring the open finds 1.0 h), the three Hollows 0.4 h, the home glide finds 0.3 h,
the first-beacon beat and new villager lines 0.3 h. Cumulative 15.0 h (INDEX).

**Save-version plan.** None. Save stays v9. New flags: the `pw:*` family (chain state), `wh:part2` (build-time only,
removed by S-104), `beacon:pinewhistle` (registered by S-095a), `beat:beacon1`, `crownShow`, `crownSeen:<n>`,
`starCount`, `visit:pinewhistle`, `gate:pinewhistle:*`, `gate:home:*` (glide finds), `scene:*`, `seen:*`, `met:*`.
New items: `glider` (tool), `pinewhistle_score` (key). Boss key `whistlehollow:mossmantle`; plushie and rematch keys
the same.
